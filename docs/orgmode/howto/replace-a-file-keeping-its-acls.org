* Replace a file and keep its access control lists

Use this when a tool rewrites a file whose owner, group, mode or access control lists (ACLs) decide who may read it, such as a module file under =/project/climate= that the project's members read through an ACL.
[[zig:zig_common.atomic.atomicWrite]] writes the new bytes to a temporary file beside the old one, gives it the old file's owner, group, mode and ACLs, reads them back, syncs and closes the temporary file, and renames it over the old file only when that close succeeds.
A close that =EINTR= interrupts is not an error and is not retried: Linux has already freed the descriptor, and the sync before the close has flushed the bytes.
[[zig:zig_common.atomic.atomicWriteAt]] closes the same way before its rename.
A reader sees the old file or the new one, never a part of either, and never the new bytes with other permissions.
[[file:../explanation/descriptor-checks.org][Checks on the descriptor, not the path]] says why each check is made on an open file.

** Before you start

- The tool depends on zig-common; [[file:../tutorials/first-tool.org][the tutorial]] sets that up.
- The tool may create files in the directory that holds the file: the temporary file, =.NAME.new=, is made there.
- The tool runs as the file's owner, or as root to replace another user's file: only root may give the new file that owner.

** Steps

1. Choose the call by what must survive the replacement:

   | Call                                   | Keeps                                                                  | For                                                     |
   |----------------------------------------+------------------------------------------------------------------------+---------------------------------------------------------|
   | [[zig:zig_common.atomic.atomicWrite]]  | owner, group, mode and every ACL form, read back before the rename     | a file whose access must not change, or not be replaced |
   | [[zig:zig_common.fsx.replaceContents]] | mode, the most native ACL form, and the owner when the tool may set it | a file in a directory the tool holds open               |

   The steps that follow use =atomicWrite=.

2. Call it with a [[zig:zig_common.atomic.Why]], which receives the reason for any failure, and free that with =deinit=:

   #+begin_src zig
   var why: common.atomic.Why = .{};
   defer why.deinit(gpa);
   common.atomic.atomicWrite(gpa, path, bytes, .{}, &why) catch |err| {
       const message = if (why.msg.len > 0) why.msg else common.atomic.describe(err);
       common.cli.err("tool: {s}\n", .{message});
       return 1;
   };
   #+end_src

   =why.msg= carries the text of an operating-system error. When the failing call names a path, the text includes that filename, or both filenames of a rename. A failed write, sync or close of the open temporary file names no path. If a failure happened before the text could be filled, [[zig:zig_common.atomic.describe]] supplies text such as =[Errno 12] Cannot allocate memory=.

3. To give the new file the access of another file, such as a file prepared beside the live one it is to replace, name that file in [[zig:zig_common.atomic.WriteOptions]]:

   #+begin_src zig
   const opts: common.atomic.WriteOptions = .{
       .metadata_from = "/project/climate/modules/Example/1.0-GCCcore-15.2.0.lua",
   };
   #+end_src

   =.mode= sets the permission bits in place of the old file's.
   A new file with neither gets mode 0644 less the umask.

** Check that it worked

Save the file's ACL with =getfacl=, from the =acl= package:

#+begin_src bash
getfacl -p /project/climate/modules/Example/1.0-GCCcore-15.2.0.lua > before.txt
#+end_src

Run the tool, then compare:

#+begin_src bash
getfacl -p /project/climate/modules/Example/1.0-GCCcore-15.2.0.lua | diff before.txt - && echo "ACL kept"
#+end_src

#+begin_example
ACL kept
#+end_example

=ls -li= shows a new inode number and the same =-rw-r-----+=: the file was replaced, not written in place, and the =+= is its ACL.
No =.1.0-GCCcore-15.2.0.lua.new= is left beside it.

** If it fails

The messages are the text of =why.msg=, after the tool's own =tool: =.

| Message                                                                       | Cause                                                                                            | What to do                                                |
|-------------------------------------------------------------------------------+--------------------------------------------------------------------------------------------------+-----------------------------------------------------------|
| =refusing to replace a symlink: PATH=                                         | the path is a symbolic link                                                                      | give the tool the path of the file itself                 |
| =cannot read access metadata for PATH: [Errno 13] Permission denied=          | the tool may not open the file                                                                   | run the tool as the file's owner, or as root              |
| =cannot preserve access metadata for PATH: [Errno 1] Operation not permitted= | another user owns the file, and only root may give the new file that owner                       | run the tool as the file's owner, or as root              |
| =temporary file must be an owned regular file with one link: DIR/.NAME.new=   | another user's file, a link or a directory has the temporary name; the tool removes only its own | look at it with =ls -l=, then have its owner remove it    |
| =access metadata of PATH changed before PATH was replaced=                    | the owner, mode or an ACL changed while the tool wrote                                           | run the tool again; the file is as it was                 |
| =unsupported access-control attribute NAME=                                   | the file has a =system.= attribute that is not one of the three ACL forms zig-common keeps       | replace the file with a program that keeps that attribute |
