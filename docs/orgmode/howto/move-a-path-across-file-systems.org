* Move a path across file systems with durable publish

Use this when a tool moves a file or directory from one mounted file system to another and must not leave a partial destination, such as moving reproduction output from =/tmp= to =/project/results=.
[[zig:zig_common.fsx.moveAcross]] tries =rename= first.
When the kernel returns cross-device, it copies to a temporary path in the destination directory, syncs and closes each copied regular file, renames that path over the destination name only when those closes succeed, and only then removes the source.
The destination is the old path or the fully copied path, never a partial tree.

** Before you start

- Hold open descriptors for the source and destination directories.
- Choose a metadata policy with [[zig:zig_common.fsx.MoveAcrossOptions]]:
  - =strict=: fail if an ACL form cannot be represented at the destination.
  - =portable=: keep bytes, owner and mode, and allow ACL downgrade when the destination does not support the source form.

** Steps

1. Build the move options:

   #+begin_src zig
   const opts: common.fsx.MoveAcrossOptions = .{
       .policy = .portable,
   };
   #+end_src

2. Call [[zig:zig_common.fsx.moveAcross]] with source and destination directory descriptors:

   #+begin_src zig
   common.fsx.moveAcross(gpa, src_dir, "capture", dst_dir, "capture", opts) catch |err| {
       common.cli.err("tool: move failed: {s}\n", .{common.sys.describe(err)});
       return 1;
   };
   #+end_src

3. Keep =strict= when the destination ACL must remain equivalent to the source.
   Use =portable= when copy success matters more than ACL form identity across file systems.

** Check that it worked

After a successful call:

- the source path is gone;
- the destination path exists;
- readers of the destination name see either the previous destination or the fully copied replacement.

For a file move:

#+begin_src bash
test ! -e /tmp/capture && test -f /project/results/capture && echo "moved"
#+end_src

#+begin_example
moved
#+end_example
